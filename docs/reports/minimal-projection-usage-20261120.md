# 会话累计用量的投影成本

## 原生提交与 PG 提交

用固定版本的 Pi Harness 跑一次完整会话。第一份模型回复同时请求两个普通工具，第二份流式返回最终文字。计数覆盖原生 `Storage.commit`，含初始化、任务状态、工具执行及流式更新。另将捕获的原生提交逐条交给原型 Projector，用真实 PG 核对事务与最终累计值。模拟工具只返回文本，本身不报告用量。原生 Pi 也允许工具和压缩模型报告各自用量。

一次实测捕获 30 次原生提交。原生提交逐条到达时，第 1–7、10–12 和 30 次共触发了 11 笔 PG 投影事务。独立的 Run 正常结束信号再用一笔事务，总计 12 笔。把同一段原生写入分别用两种设置重放，触发事务的位置完全相同。开启组第 1 次建空用量行，第 6 和第 30 次随助手消息更新这行。流式文字没有写到 PG 正文。测试工具在内存返回固定值，这个事务数不能外推到含真实沙箱派发的 Run。流式提交总数受分块和调度影响。

## 容量实验口径

两组从同一发送进程重复投递同一份已编码的 Kafka 记录。两组助手正文均含本次用量，原生提交均含全量 `pi.usage`。两组均识别用量文档 ID，恢复点仅附带其 Conversation 归属。开启累计值投影后，在已有合批调用中，使用同一帧已获接受的消息或 Inbox 身份，把最新值覆盖到租户、物理 Session、Conversation 对应的 PG 行。累加由 Pi 完成。重放已覆盖的分区前缀会跳过整批，旧身份的拒绝不写用量，冲突会使正文、用量及进度一起回滚。没有单独按片段推算 token 的逻辑。

每轮 256 个 Run，每个 Run 有 100 对约 4 KiB 的工具调用和结果，以及开头输入与末尾回答。每个 Run 有 101 个模拟模型回复，对累计行产生 1 次初始化和 101 次覆盖。每轮另行校验 51,712 条 PG 消息的内容摘要、256 次正常收尾及累计行的全部计数和位置。速率分子按此前口径只计 51,200 条中间完整消息，其他记录的处理时间计入分母。每份累计值有一个模型桶，工具桶为空。

真实三副本 Kafka，32 分区，一个原型 Projector，12 个 PG 连接，同分区最多合 16 条已到达记录。两组使用同一无额外覆盖索引的 Fork 存储布局。隔离 PG 17.6 实例默认同步、开启 fsync，在每笔被测投影事务内切换为异步确认并核验。定速组的 P95 从计划发出到 PG 确认，以毫秒计。预装积压组从所有记录已获 Kafka 确认才开始计时。WAL 取隔离 PG 实例测量窗口内的写入位置差，包括正文、索引、恢复点、事务和全页镜像。

## 结果

两份独立数据和临时数据库各跑 12 轮，先后顺序分别为关、开、开、关和开、关、关、开。每档每种设置有四个样本。表中吞吐和 P95 均取四轮对应测量的中位数。P95 的区间为各轮 P95 的最小和最大值。

| 负载 | 关闭累计值投影 | 开启累计值投影 |
|---|---:|---:|
| 2,315 条/秒，实际完整消息/秒 | 2,314 | 2,314 |
| 2,315 条/秒，P95（范围） | 27 ms（25–29 ms） | 27 ms（24–31 ms） |
| 6,000 条/秒，实际完整消息/秒 | 5,794 | 5,433 |
| 6,000 条/秒，P95（范围） | 0.42 s（0.29–2.06 s） | 1.53 s（0.25–2.59 s） |
| 预装积压，排空速度（条/秒） | 6,977 | 6,840 |

在 2,315 条/秒档，停发后两组均在 14 ms 内追平。6,000 条/秒档，第二套夹具的开启组有两轮 P95 达到 2.58–2.59 秒，关闭组也有一轮达到 2.06 秒。最慢的开启组发送端迟到 P95 仅 1.31 ms，观测到的 Kafka 末尾与投影进度之差最大为 10,589 条，停止投入后用 1.73 秒排空。此处观察到消息在投影链路上排队，未单独计时 PG 内部每一条 SQL。高峰开启组中位吞吐低 6.2%，预装积压组低 2.0%。4 次/组的短窗口不足以把全部长尾归因于累计值写入。

对 12 个开启和 12 个关闭样本分别求和，开启组多写约 3.9% 实例 WAL，折合每个累计行写入平均多约 521 字节。即使最终每个 Conversation 只保留一行，也会产生实际写入成本。所有正式轮次最终积压为零，共校验 1,228,800 条计数消息。每轮开启组把 26,112 次写入投影成 256 行，最终内容逐字段验证通过。

## 适用范围

该实验覆盖普通响应共提交的最新值。被测容量不含真实模型推理、完整工具派发、沙箱执行、实时文字流量，或服务端实际 HTTP `/usage` 读取。尚未在新原型接入面向用户的 `/usage`、多子会话汇总、冷开 Harness 的完整文档导入或费用结算。实验在单独的性能分支和临时资源中完成。26 项原型辅助测试和 6 项真实 PG／Kafka 集成测试均通过。临时数据库、Topic、消费组及临时 Pod 等已清理。
