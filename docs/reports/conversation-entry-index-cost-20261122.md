# Conversation 正文索引的读写成本

建议在面向长会话和多子 Agent 的候选原型中采用这个部分索引。实测改善最大的是查历史时的 PG 缓冲页访问次数。积压回放中，Projector 吞吐中位数低了 2.6%，各对照组的时间波动超过这个差距。更稳定的代价是混合工作负载的 WAL 增加 3.5%，以及索引本身占用的空间。此次仅在可销毁的 PG 实例上创建索引。

```sql
CREATE INDEX study_lane_entries
ON messages (tenant_id, pi_session_id, conversation_id, entry_id)
WHERE entry_id IS NOT NULL;
```

## 同一份消息经过实际 Projector

使用 PostgreSQL 17.6、RF3 Kafka、32 个分区、一个 Projector 和 12 个 PG 连接。一次在线 Pi 生成确定性负载，随后验证每次回放的内容哈希。每轮包含 1,024 个根 Run，每个依次执行 20 个模拟 Bash 工具、结果 1 KiB、设备确认延迟 100 ms。每轮核对 191,488 条 Kafka 记录、44,032 条完整历史、20,480 对有序调用与结果、全部终态和最终消费位置。它测量热路由下的投影和派发；入队、模型服务和物理沙箱执行各自独立。

| 指标 | 无索引 | 有索引 |
| --- | ---: | ---: |
| 预先积压后排空，Run/s | 21.11 | 20.56 |
| 相同排空窗口，完整正文行/s | 907.94 | 883.95 |
| 工具意图投影阶段的 P95 上界 | 9.92 ms | 9.92 ms |
| 每轮写入的 PG WAL | 166.98 MiB | 172.81 MiB |
| 每轮新增索引本身的大小 | 0 | 3.91 MiB |
| 固定输入 3,247 条 Kafka 记录/s，Run/s | 17.17 | 17.17 |

先积压再排空共 8 轮，按无/有、有/无、有/无、无/有的相邻轮次配对。表中是各自 4 轮的中位数。配对吞吐差依次为 −7.85%、+8.09%、−3.36%、−3.91%。P95 来自工具意图或意图批次的 PG 投影阶段，取每轮直方图上界的中位数。WAL 统计的是专用 PG 实例上从写入位置起止点得到的字节差，覆盖整轮投影。两组都在准备数据后执行 CHECKPOINT，建索引与种子数据写入在窗口外。

固定输入另做 4 轮并反转顺序，两种配置都追平。最后一次 Kafka 输入确认后，完成剩余投影和模拟回执约需 0.52～0.58 秒。这个输入速率低于本次排空能力，因而不能只凭此档判断峰值性能。

在高压组，索引空间约为每条完整正文 **93 字节**，在本组工作量和填充率下成立。正文表的全部索引空间从约 10.49 MiB 增至 14.34 MiB。配置文档行不在新增部分索引内。

## 单看 PG 正文追加

在另一个专用、2 vCPU 的 PG 17.6 中，八个物理 Session 各含 128 条 Conversation。取一份固定 Pi 的 20 工具原生 Entry 样本，复用其正文形状、交错各条会话的 Entry 位置，预先准备输入。保留候选表上的约束、外键和原有索引。每轮先插入 132,096 条历史，再由一个后端用一条 INSERT 追加 44,032 行。丢弃两轮暖身，随后再做四对正反序对照。

| 指标 | 无索引 | 有索引 | 中位数变化 |
| --- | ---: | ---: | ---: |
| 追加的服务端执行时间 | 1,333 ms | 1,553 ms | +16.5% |
| 该批写入的 WAL | 65.23 MiB | 80.32 MiB | +23.1% |

服务端时间来自 EXPLAIN ANALYZE，包括外键触发器；WAL 起止位置覆盖提交。这是单后端、大批量、已有历史且多会话交错的追加测试。其时间占比与包含 Kafka、工具派发及其他 PG 更新的混合链路不同。四对耗时差为 −10.56%、+17.92%、+12.35%、+19.48%，全部原始轮次均保留。

## 同机读取收益

在 500 个历史子 Agent、总计 16,032 条正文的数据库上，用 5 个全新的 Worker 内存 Storage 读取暖缓存 PG。两种配置都严格返回 32 条主线正文，用到指定子 Agent 时再返回它的 32 条。依次测试无索引、有索引，并删掉临时索引再次测量同一数据库。

| 操作 | 无索引 | 有索引 | 移除后复测 | 正文 SQL 缓冲页访问（无 → 有） |
| --- | ---: | ---: | ---: | ---: |
| 主线冷启动 | 6.6 ms | 4.1 ms | 5.6 ms | 1,604 → 7 |
| 首次读取指定子 Agent | 7.8 ms | 5.0 ms | 6.3 ms | 1,613 → 14 |

缓冲页访问包含命中及重复访问，与实际从磁盘读了多少页是不同的指标。每次调用在这个小型暖库上只节省几毫秒，但为定位同样 32 行，PG 访问的数据已明显减少。本轮没有测同时发生的大规模线上历史查询，也没有测在线建索引的时长和锁等待。
