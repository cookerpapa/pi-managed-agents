# Reconciling the storage prototype with the independent Session deployment

This review follows the owner's design conversation from the November 15 load study, through the November 18–19 decision to rebuild storage incrementally, to the November 28 direct-Turn claim measurement. The integration target is the image entry under scripts/serving/independent-session and its authenticated API, Worker, partition consumer and deployment schema. A passing test on a different composition establishes the behavior of the tested component only.

## Conflicts found in the combined path

1. A terminal fact is replayable, but its PG trigger can select an unadopted PG-only message and generate a **random new Turn and idempotency key**. In the interval after an asynchronous commit becomes visible and before its WAL is flushed, a client could see the new ID. A PG crash in that interval would lose it. Replaying the terminal fact would generate a different ID. A subsequent synchronously committed claim also flushes the earlier WAL and closes this particular window. The new-identity side effect requires a synchronous boundary or a stable, recoverable successor identity. Recovery gating alone cannot retract an ID returned before a crash. See [the trigger](../../scripts/experiments/minimal-session-storage/turn-ready.sql).
2. The moving projection checkpoint and the complete native takeover witness serve different consumers. IndependentSessionRuntime also rewinds to the earliest active turn's output_first_offset. Frequent recent output alone does not move that second floor. An active or abandoned Turn older than retention can currently block the partition after restart. Handling only the abandoned Turn safely requires distinguishing a lost private reconstruction prefix from loss of the partition's unprojected messages. The latter must stop the partition. See [assignment bootstrap](../../scripts/experiments/minimal-session-storage/independent-session-runtime.mjs).
3. The narrow history-only batch predicate excludes every commit in the recorded 20-tool trace. Enabling that predicate on the new consumer would have produced a passing entry-only benchmark and zero eligible records on this mixture. The serving fold now prepares intermediate states for mixed native commits before publishing their UI events. Physical effects still require their own ordered grant.
4. Native code and the input ledger use different evidence for user Stop, a placement receipt, and a shell process exit. A visible cancellation cannot prove the shell exited. A child creation receipt cannot prove its first model request completed. The independent executor and input pump preserve these separate acknowledgements.

## Actual schema dependencies

The following inventory describes installation version 2. [Version 3](independent-turn-references.md) has migrated those references.

A catalog query on a fully migrated, disposable PG17 database found eleven foreign keys from ten public tables to public.runs. A search through historical migration text overcounts these links. The physical target matters because the segmented runs compatibility view addresses turns and cannot be the target of a PG foreign key.

| Public referencing table | Use to review at matched cutover |
|---|---|
| session_schedules | The scheduler sets last_run_id on fire. Both the transaction that admits the input and the foreign key need the same Turn authority. |
| session_upload_pins | Pending attachment ownership currently expects a Run. Rebind to the mailbox or Turn with the correct withdrawal, adoption and collection lifetime. |
| execution_target_bindings | Physical executor bindings must address the admitted Turn and retain the original cancellation target. |
| run_skill_catalogs | The per-Turn Skill snapshot uses a composite tenant/Run reference. Preserve tenant scoping across the change. |
| source_control_issue_jobs, environment_validations | Verify the remaining callers and their completion/cleanup path before retiring or moving their references. |
| run_transitions, session_terminal_events, turn_control_requests (two keys), subagent_conversations | The candidate has its own terminal rows, independent child Sessions and control state. Migrate surviving readers before dropping obsolete write paths. |

Reproduce with the following read-only query after running the maintained migrations.

```sql
SELECT conrelid::regclass AS referencing_table, pg_get_constraintdef(oid) AS definition
FROM pg_constraint
WHERE contype = 'f' AND confrelid = to_regclass('public.runs')
ORDER BY 1, 2;
```

A fresh empty installation still creates these references. Duplicating each Turn into public.runs would restore dual execution authorities. A matched switch should explicitly assign each consumer to the segmented Turn, mailbox or Session, then retire the old writers. The partial candidate API consequently keeps legacy compact/admission and attachment mutations closed. The serving Guest route also needs the actual resource manager and completion endpoints. A replay after history truncation must look up the route by physical Flow while delivering the operation to the public Session. The routing adapter and its cold cancellation probe now use those distinct identities.

## Measurement

The fixed trace contained 20 model tool proposals, 20 canonical results and one final answer across 186 native commits per Turn. A separate terminal Kafka record closes the Turn. Each measured arm submitted 480 distinct Sessions at four arrivals/s to four partitions on RF3 with a two-CPU PostgreSQL budget. Both used the same recorded trace with SHA-256 deeef6de5a8127e1a50db964e180c87076e1113c3cb7eacec22a5d39825e22b0. The mixed fixture replays Pi writes and delays tool results by 50 ms. ### Final matched images

Two additional serial runs used the same API, Worker, Projector, named executor and retained Tool host image set. Each submitted 480 Sessions and verified 19,680 visible records. The acceptance also ran real Harness tool calls against owned HTTP endpoints after the timed interval. The table separates the last client acknowledgement from the last producer acknowledgement. The latter ends at the first observation that all Turns are sealed, with a 200 ms poll interval.

The transport/failure suite passed 55 tests in 31 files. The independent MCP suite exercised an in-flight schema change, explicit disable, canonical replies and takeover. The routing crash probe exercised separate public Session and physical Flow identities, a lost cancellation acknowledgement, and the warm/cold original route lookup. The serving gate also stopped a running child through the public API and verified that its parent completed. A diagnostic-only trial failed to collect the last producer ACK via a process signal; the fixture now emits its aggregate when the final measured ACK arrives. The table uses successful, end-to-end runs. A separate live-provider Chrome check completed two streamed Turns on two different Workers, observed both SSE completions, and verified the retained answers after two browser refreshes (51.65 s). All workspace type checks passed.

## Repeat the serving check

From the candidate checkout, set the maintained control-plane and Worker base image references as in the [original image gate](independent-session-serving-20261127.md). The harness creates a disposable PG database, RF3 broker cluster, private tenant and dedicated Session topic. It can capture its own native tape on a clean checkout. To compare revisions, supply the same tape to both.

```sh
export TSX_TSCONFIG_PATH="$PWD/packages/control-plane/tsconfig.json"
node scripts/build-independent-session-images.mjs reconciled
PI_CLOUD_CHECK_PG_CPUS=2 PI_CLOUD_CHECK_TURNS=480 PI_CLOUD_CHECK_ARRIVALS_PER_SECOND=4 \
  node --import tsx scripts/run-independent-session-serving-check.mjs reconciled --load --mixed
```

The serving composition requires an independent delegation endpoint and a versioned Tool host for the same installation. The Worker restores the published platform catalog before accepting work. The check drives the actual Session API and verifies the call IDs, result IDs, terminal answers and final PG offsets. Additional functional checks invoke an HTTP MCP service, schedule a named child, query child context, query the frozen prefix of a new Web Fork, and verify that the Fork has its own usage and no inherited child family. The mixed replay replaces only the measured Worker execution function; none of its 20 tool proposals requests an external effect. The subsequent functional calls use the unmodified Worker execution function.
