# ADR-0356. Run-boundary history branches and explicit directory recovery

Accepted for the isolated #48 candidate. Use a Session's flow ID for new root Runs and its head Run ID for reading. Each root Run retains its writing flow and history predecessor, immutable after claim. A new Session can point into another flow before accepting its first input. Branch at a completed, sealed Run boundary. Preserve consumed steer/follow-up within that Run. Quiescent prune moves the head and starts a new writable flow. Adjacent unstarted inputs can reorder their provisional links together with their queue positions under the Session lock. No scheduling row represents a Fork. Session settings, Workspace and directory belong to the public window. A claim pins its execution context. Verify the linked representation with PostgreSQL transactions, existing Kafka/PG projection, indexed history reads and bounded asynchronous cleanup before considering a matched cutover.

Protect all live heads and history predecessors with tenant-scoped constraints and indexed lookups. Detach a window and enqueue its prior head atomically. GC stops at any remaining reference. Compare bounded latest-page reads, fork membership, cold context and exclusive-tail cleanup with 1,000 to 100,000 Runs. The previous immutable range directory remains a comparison until the new layout passes the serving gates.

A fixed Guest failure to open the selected user directory before tool execution is a structured tool result. Preserve that result before terminating the affected native work without a further model request. File lookup errors and ambiguous infrastructure failures keep their existing policies. A fresh authorized Run uses its newly selected binding, while pending work is withdrawn explicitly and its input remains available. No directory probe is generated for text-only turns.
