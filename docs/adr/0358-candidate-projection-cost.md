# ADR-0358. Validate candidate page lookups and projection write costs

The #52 experiments use the existing PostgreSQL primary, native Pi commits and Kafka partitions. Promote the measured exact Entry lookup for candidate pages with tenant, physical stream, Conversation and Run checks. Compare the same HTTP pages with the previous query, including pending Tools and frozen branches.

In a disposable database test whether an already admitted ordinary message can use the partition progress transaction alone. Race a delayed transaction with closure, replacement and recovery, including progress between the two positions. Keep the Run guard wherever progress cannot establish admission. Separately test projecting pending sandbox waits in memory with handoff/replay. Evaluate original deadlines, cancellation, history and the reply retention floor while the owner is unavailable, including history outside broker retention. An unavailable protected suffix cannot authorize redispatch or deletion. Keep the verified PG path wherever the experimental contract fails.

Use one 20-Tool-per-Run tape for the comparisons and distinguish delivery, database projection and browser presentation. These experiments do not authorize a serving cutover, altered retention or changes to Pi.

The candidate combines the existing guarded Run updates when their scope and native frame match. Keep a durable pending reference until a cold reader and a retention client can establish its original reply floor without the current Projector. The isolated stale-admission and wait alternatives remain experiments. [Results](../reports/candidate-page-and-write-cost-20261124.md).
