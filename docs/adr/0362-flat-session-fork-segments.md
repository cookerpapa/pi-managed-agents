# ADR-0362. Store frozen ancestor ranges on each candidate history flow

Accepted for the isolated storage candidate. Use the existing PostgreSQL message projection and indexed source coordinates. A branch owns an ordered list of inherited ranges and an implicit local append tail. Each range identifies the original physical stream, native Conversation, Entry boundary and publication ceiling. A fork inside an ancestor copies only preceding descriptors and clips that ancestor. Cold reads, presentation and collection respect both coordinates. Incoming references protect source data independently of the lifetime of its window. Normal message appends never enumerate descendants.

Use Temporal's range-list algorithm as researched in the [review](../research/session-fork-design-review-20261125.md). Human forks select sealed Turn boundaries. A delegated branch selects the committed cutoff of the model request which produced its call. Fresh delegation inherits no history. Keep Pi's document and context semantics, including current resource observations and historical agent configuration. Session names, management ancestry and history ancestry are separate. Capacity for this study is sufficient; independent scheduling and slot exhaustion remain deferred. A matched production cutover has a separate acceptance gate.

Branch-capable model requests preserve their publication ceiling on the existing native Run document. The Worker associates a returned delegation with its generation and call ID. The candidate executor resolves the Entry on the visible path and checks the original request ceiling when pinning it. Header uploads are retained with the Turn. A follow-up attachment is exposed when its canonical Entry is visible.
